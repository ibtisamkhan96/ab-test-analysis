# A/B Test Analysis — Checkout Page Experiment
**Analyst:** Ibtisam Ahmed Khan  
**Dataset:** Udacity A/B Testing Dataset  
**Tools:** Python, pandas, numpy, matplotlib, scipy, statsmodels  

## Business Question
Did the new checkout page produce a statistically significant improvement 
in conversion rate — and should we ship it?

## Dataset
- ~290,000 unique users split 50/50 between control and treatment
- Control group: saw the existing old checkout page
- Treatment group: saw the new challenger checkout page
- Outcome: converted (1 = purchased, 0 = did not purchase)

## Analysis Structure

| Section | What it covers |
|---|---|
| 1. Data Loading | Shape, columns, data types, missing values |
| 2. Data Cleaning | Mismatch removal, deduplication, timestamp parsing |
| 3. Experiment Overview | Group summary, conversion rates, sample ratio mismatch check |
| 4. Hypothesis and Sample Size | Formal hypothesis, required sample size calculation, power check |
| 5. Statistical Test | Two-proportion z-test, p-value, 95% confidence interval |
| 6. Daily Trend Analysis | Novelty effect check — does B fade over time? |
| 7. The Peeking Problem | Simulation showing why stopping early inflates false positive rate |
| 8. Segment Analysis | Conversion rate breakdown by day of week |
| 9. Final Recommendation | SHIP or DO NOT SHIP decision with full analytical audit trail |

## Key Findings
- Control conversion rate: ~12%
- Treatment conversion rate: ~12%
- The difference between the two groups is not statistically significant
- **Recommendation: Do not ship the new page** — it does not produce a reliable improvement

## What Makes This Analysis Rigorous
Most A/B test analyses just run a single statistical test. This notebook goes further:

- **Data quality checks** — mismatched group/page assignments removed before analysis
- **Deduplication** — each user counted exactly once
- **Sample ratio mismatch check** — verified randomisation was not broken
- **Sample size validation** — confirmed sufficient power before trusting results
- **Novelty effect check** — daily trend plotted to detect fading treatment effect
- **Peeking problem simulation** — demonstrates why stopping early inflates false positive rate to ~30%
- **Segment analysis** — result verified across days of week

## The Peeking Problem
One of the most important sections in this notebook demonstrates what happens 
when analysts peek at results daily and stop the moment p < 0.05. The simulation 
shows the p-value fluctuating above and below the significance threshold as data 
accumulates — proving that early stopping produces unreliable decisions.
